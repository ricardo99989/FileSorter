# 玻璃化界面设计规范（3.5 版）

这份文档不是审美宣言，是**验收清单**。下面每一条都对应一处代码，写在 `tokens.css` /
`glass.css` / `material.css` / `wheel.js` 里。改界面之前先读它，改完之后逐条对。

来源：9 篇小红书 UI / 玻璃化 / 动效笔记的实拍与拆解（见文末「出处」）。

---

## 一、玻璃到底靠什么成立

看完那批参考图，最反直觉的一条结论：

> **玻璃好看不是因为玻璃本身，是因为它后面有东西。**

同一块 `backdrop-filter: blur(20px)`，铺在纯色底上就是一块脏抹布，
压在照片、渐变球、有明暗起伏的背景上就是玻璃。
参考图里所有"通透"的例子，背景要么是水面、要么是城市夜景、要么是柔焦的球体。

所以第 0 步永远是背景：

1. 背景必须有**明暗起伏**，不能是纯色。
2. 起伏要**柔**（大半径径向渐变，不要硬边形状）。
3. 至少有一个**高亮区**（偏白）和一个**阴影区**（偏蓝灰），玻璃滑过去才会有明暗变化。

我们的做法：`--bg-0/1/2` 三级近白，叠两团大半径径向渐变（蓝灰 + 淡紫），
外加一层 3% 的颗粒噪点压色带。**只留两团**——第三团会让背景重新变花。

## 二、五步玻璃法

参考笔记《五个步骤教 Agent 做出有层次的玻璃界面》给的是这条链路，
每一步都对应一层 CSS，缺一层就"平"：

| 步 | 做什么 | 代码位置 |
|---|---|---|
| 1 模糊 | `backdrop-filter: blur(N)`，N ≥ 20 | `.glass` / `.grid-card` |
| 2 增色 | 玻璃本体带一点底色，不是纯白；`saturate(180%)` 把背后颜色提上来 | `--glass-1/2/3` + `saturate()` |
| 3 叠白 | 顶部叠一层 `linear-gradient(180deg, white, transparent 42%)`，模拟玻璃厚度 | `.glass::before` |
| 4 亮边 | **1px** 高光描边（白 20%）+ 顶部 1px 更亮的发丝线 | `--glass-stroke` / `--glass-hair` |
| 5 折射 | 边缘内阴影 + 极轻的色散（只在大面板用，滥用会脏） | `.glass` 的 `inset` 阴影 |

第 4 步是最容易被写错的一步：**描边要细、要淡**。
参考图里的边几乎看不见，只在转折处闪一下。粗白边 = 塑料，不是玻璃。

## 三、五种玻璃风格，我们只取两种

参考笔记把玻璃化拆成 Skeuomorphic / Spatial / Liquid / Soft Glassmorphism / Neumorphic 五类。
桌面工具只能取两种，混用必翻车：

- **Soft Glassmorphism** —— 主界面。近白半透明卡片、大圆角、柔和阴影、低对比。
  理由：长时间浏览文件，高对比会累；而且浅底配深字最省眼。
- **Spatial Glass** —— 深色主题与浮层（抽屉、弹窗、右键菜单）。
  理由：深色下近白卡片会脏，改成"暗玻璃 + 顶部亮边"才有悬浮感。

**不取** Liquid Glass 的强色散和 Neumorphic 的双向阴影：
前者在文字密集界面会干扰阅读，后者和"半透明"天然冲突（不透明才做得出凸起）。

## 四、配色：两个颜色，其余全是灰（3.2 最终）

- 主色 `--accent` 雾蓝灰 `#8A9BAE`：选中态、主按钮、进度、滑块。
- 强调色 `--lilac` 淡灰紫 `#B0A8C9`：只用于「需要被看见一次」的地方。
  **一屏超过两处就不叫强调色了。**
- 玻璃本体唯一允许的白是 `rgba(255,255,255,.1)`；文字走 `--ink-1..4` 四级灰。
- **不要渐变**。主按钮、开关、状态标签、背景一律纯色。渐变会把"一片玻璃"
  拆成两段色温，通透感立刻碎掉。3.1 那道蓝→紫的按钮渐变已撤。
- **不要彩色标签**。分类色全部收进灰系、饱和度压到 10% 以下，只靠极淡明度差分辨：
  图片=浅灰蓝、视频=浅灰紫、文档=浅灰青、其余=中性灰。旧数据里的
  `amber` / `rose` / `sage` 统一落到 `--tone-slate`，不留下空洞。
- 状态（成功 / 警告 / 危险）也不另起色相，只在同一灰蓝里改明度和字重。
  一屏出现第三种色相，极简就破了。

## 五、排版：层级靠三件事，不靠四种字号

参考图里几乎只有两个字号档：**标题档**和**说明档**。层级是靠这三件做出来的：

1. **字重**：标题 600，正文 400/450。
2. **颜色**：标题 `--ink-1`，说明 `--ink-3`（不是更小的字号，是更浅的灰）。
3. **字距**：小号全大写标签加 `letter-spacing: .08em`，立刻有"标签感"。

反面教材是我们 3.0 的卡片：文件名 12.5 / 说明 11 / 元信息 10.5 三档挤在一起，
结果是"哪一行都不重要"。现在改成 13 / 11.5 / 10.5 但**说明行统一降到 `--ink-3`**，
靠颜色分档，字号只差一档。

留白：卡片内边距 `16px 16px 14px`，网格间距 10px，面板内边距 16~20px。
**宁可少放一个文件，也不要挤。** 所有文字严格左对齐，标题、说明、元信息共用
同一条左基线，不做居中、不做"标题居中正文居左"的混排。

## 六、圆角与阴影

- **圆角全局只有一档 12px**（开关/标签这种必须全圆的才用 `--radius-pill`）。
  3.1 的 10/12/16/20 四档并存，同一屏能出现三种圆角，视觉上立刻显乱。
- 阴影只三档，且都带蓝调（不用纯黑，纯黑发脏），**整体极淡**：
  - `--shadow-1` 静置
  - `--shadow-2` 悬停
  - `--shadow-3` 浮层
- 玻璃边缘只留 **1px 白色 15% 高光描边**，厚度靠缘光而不是描边加粗。
- 悬停位移统一 `translateY(-2px)`，不许多。

## 七、动效：只动 transform / opacity / filter

参考笔记反复强调"丝滑"，而丝滑的技术前提是**不触发重排**。
所以我们只碰 `transform`、`opacity`、`box-shadow`、`filter`。

- 时长：150（微反馈）/ 190（常态）/ 260（入场）/ 320（模式切换）。
- 缓动：入场用 `cubic-bezier(.16,1,.3,1)`（先快后慢，像东西落定），
  其余用 `cubic-bezier(.22,.61,.36,1)`。
- 入场一律**淡入 + 上滑 8px**，不缩放（缩放会糊文字）。
- 列表逐项入场：`delay = index * 14ms`，**上限 12 项**。超过就不再错开，
  否则滚动到底部时最后一项要等半秒才出现。

## 八、轮盘：为什么用"描边弧"而不是"扇形路径"

圆角扇形要做贝塞尔内缩，代码 200 行，还容易在窄扇区上算错。
换成 **粗描边 + `stroke-linecap: round`** 的圆弧：

- 圆角自动有了，且永远是正圆角；
- 弧宽就是扇区宽度，`stroke-width` 一个数控制粗细；
- 扇区之间用空隙隔开，空隙是**背景**，天然形成分割线，不用画描边。
  空隙不是想给多少就给多少：圆头端点本身就占 `width/r ≈ 12°`，
  gap 必须 ≥ 15°，3° 会让相邻扇区咬合、分隔线消失。

窄扇区兜底：`end - start < 1.5°` 时退化成中点 ±0.75° 的短弧，靠圆头画成圆点，
否则 `A` 命令会反向把整圆涂满。3.2 又把六个扇区的色相全部收进灰系
（`slate` / `blue` / `violet` / `teal` / `slate` / `mist`），退远看是一整片灰。

代价是扇区只能是环带（不能做成从圆心出发的实心扇形）——但环带正是
参考图里那种"分段进度环"的样子，反而更贴合。

计数放哪：扇区弧长 ≥ 20px 才把数字画在弧上（白字），
更窄的扇区只把数字留在图例里。硬塞进去会溢出，比不显示更糟。

## 九、3.2 补充：把桌面本身变成背景

3.1 的玻璃全是"应用自己画背景、自己糊自己"。3.2 换了架构，这一节记的是**为什么换**和**换的边界在哪**。

### 9.1 `backdrop-filter` 有一个物理上限

 Chromium 的 `backdrop-filter` 算子集是封闭的：

| 它有 | 它没有 |
|---|---|
| `blur` `brightness` `saturate` `contrast` | **位移**（→ 没有折射） |
| `hue-rotate` `sepia` `grayscale` `invert` | **分波长采样**（→ 没有色散） |
| `opacity` `drop-shadow` | **环境反射** |

采样一次、线性变换、叠加——这条管线里不存在"光线穿过介质后改变方向"的概念。
所以 3.1 的五步法里第五步"折射"用的是内层线性渐变，**那只是高光，不是折射**。
当时把它列进"已完成"是不准确的，这里更正。

### 9.2 窗口不透明时，`blur` 连桌面都摸不到

更根本的问题：窗口底板不透明（`backgroundColor: '#e9ecf2'`）时，
`backdrop-filter` 的 backdrop 只有应用自己画的那两团渐变。**模糊一块浅灰，结果只是更灰。**

要真透出桌面，只有一条路：让 Windows 的桌面窗口管理器（DWM）来合成。

```js
new BrowserWindow({
  frame: false,
  backgroundColor: '#00000000',      // 底板全透明
  backgroundMaterial: 'acrylic',     // 由 DWM 在窗口背后画毛玻璃
})
```

`backgroundMaterial` 和 `transparent: true` 在 Electron 里**互斥**，正确写法是
不透明窗口 + 全透明页面，别两个一起上。

实测结论（`_probe/` 下留有探针）：

- **acrylic 能透，mica 几乎不能透**（纯白板），tabbed 明显偏绿直接排除；
- Windows 11 的 acrylic tint 偏奶白，所以页面里**不能再叠白**——
  3.1 那套 68~88% 白度全部作废，改成 3.5%~18%；
- tint 的明暗跟**系统**主题走，不跟应用的 `data-theme` 走。
  应用切深色而系统还是浅色时会得到"浅色玻璃 + 白字"，一个字都看不见。
  解法是建窗前把 `nativeTheme.themeSource` 钉成应用主题；
- 运行期改 `themeSource`，DWM 会在 **300~500ms** 内重采样 tint。
  渲染层的主题交叉淡变因此定在 440ms，两边同步过渡，不露马脚。

### 9.3 只有一层玻璃，其余全部退场

四层玻璃（侧栏 → 主面板 → 卡片 → 抽屉）各 blur 一遍，每层都削一次对比度，
最后整体灰且平。**全部都做成玻璃，等于全都不像玻璃。**

acrylic 档位下的分工：

| 谁 | 负责什么 |
|---|---|
| DWM | 桌面模糊（唯一的真模糊） |
| `.app-bg` | 两团很淡的冷色渐变，把系统偏暖的 tint 压回冷调 |
| `.glass::before` | **缘**：四条 inset，上亮下暗左亮右暗，1.5px |
| `.glass::after` | **面**：纵向渐变，模拟光在介质里自上而下衰减 |
| `backdrop-filter` | 全局归零。它们糊不到桌面，纯粹重复劳动 |

厚度从此来自**边缘**而不是整块叠白。真玻璃立在桌面上被左上方来的光打中时，
光分两路：打在斜边上的一条要锐，穿过玻璃在里层衰减的一条要柔。
`.glass::before` 管前者，`::after` 管后者。

### 9.4 真折射：SVG 位移滤镜，不是 WebGL

WebGL 做不了这件事——`gl.readPixels` 读的是自己的 framebuffer，拿不到窗口外的像素。
而 `backdrop-filter: url(#filter)` 可以引用页面里的 SVG 滤镜，
其中 `feDisplacementMap` 会**按位移图重新采样背后的画面**，这才是真正的"光拐了弯"。

```svg
<filter id="liquidRefract" color-interpolation-filters="sRGB">
  <feTurbulence type="fractalNoise" baseFrequency="0.007 0.011" numOctaves="2" seed="17" result="warp"/>
  <feDisplacementMap in="SourceGraphic" in2="warp" scale="14"
                     xChannelSelector="R" yChannelSelector="G"/>
</filter>
```

- `baseFrequency` 压到 0.007/0.011：频率一高就成噪点，不像液体；
- `scale` 14px 是"能看出来但不影响读字"的上限；
- **只挂在浮动层**（抽屉 / 菜单 / toast / modal）。它们下面压着文件卡片这类
  页面自己的内容，位移才有东西可折。主面板不行——桌面是 DWM 画的，
  在页面之下，backdrop 采不到。

实测性能：抽屉开启时 p99 帧时 6.8ms，关闭折射时 6.7ms，
差异在噪声范围内，远低于 16.7ms 的 60fps 预算。
`feTurbulence` 是静态种子，只算一次；每帧只是一次纹理采样。

对照实验（`_probe/inject.js`）：同一个位置三个块，无滤镜 std=4.18、
只模糊 std=0.88（结构全糊平）、模糊+折射 std=6.54（结构恢复 7.4 倍）。

## 十、3.2 最终约束：极致通透、克制配色、可调雾度

最后一条需求是「越透明越好，文字可读即可」+「舍弃多颜色，只要少量克制配色」。
这一节是落地的验收口径，与第四、六节一起看。

### 10.1 透光预算：86%~90%

| 层 | 白度 | 说明 |
|---|---|---|
| 非 acrylic 回退档 | 10% / 14% / 18% | `--glass-1/2/3`，配 `blur(30px)` 的桌面模糊 |
| acrylic 档 | 4.5% / 10% / 18% | 系统已经给了 tint，再叠同量级的白只剩一片奶 |
| dock 小窗 | 2%~3% | 异形挂件最该像「贴一片玻璃在桌沿」 |

3.1 的 68/78/88% 是"磨砂塑料"：整块均匀叠白，通透感全无。现在**可读性不靠刷白面板**，靠三条：

1. `--text-lift`：贴字的一道 1px 淡影（浅色白影、深色黑影），刻意不加 blur 半径 ——
   模糊阴影每个字符都要多渲一遍，虚拟滚动的长列表会直接掉帧；
2. 分层：越需要读字的地方越实（侧栏 5% → 主区 8% → 详情 12%），
   而不是全界面一个透明度；
3. 深色 acrylic 的 tint 偏亮蓝灰，`--ink-3/4` 整体提一档到 `#B4BDCC / #949DAD`，
   透明度一点不用让步。

### 10.2 为什么还需要「玻璃雾度」滑块

acrylic 的 tint 由系统绘制，压不过桌面原本的颜色：窗口放在绿壁纸上会发绿、
放在暖色壁纸上会发黄。应用唯一能自己控制的是 `.app-bg` 那层冷白薄膜：

```css
linear-gradient(180deg,
  rgba(233, 238, 247, calc(var(--mist) / 100)),
  rgba(228, 235, 245, calc(var(--mist) / 100)))
```

`--mist` 默认 14、范围 0~30，在 `store`（v4）里持久化，设置面板「外观」页实时可调。
0 = 完全交给桌面，30 = 色温稳但少一点透；深色档除以 130 再压一档，
否则白雾会把暮色桌面洗亮。**这是"不断接近完全透明"的旋钮，不是第二个模糊参数。**

### 10.3 分工表（最终）

| 谁 | 负责什么 | 不负责什么 |
|---|---|---|
| DWM acrylic | 桌面**模糊**、tint 明暗 | 不认应用的 `data-theme`，只认系统主题 |
| CSS 缘光 / 壁厚 | 1px 15% 高光、上亮下暗的厚度 | 不再整块叠白 |
| SVG `feDisplacementMap` | 浮动层压在页面内容上的**折射** | 折不到桌面（桌面在页面之下） |
| `--mist` | 把桌面色温按回雾蓝灰 | 不做第二层模糊 |
| `backdrop-filter: blur(30px)` | 仅 Windows 10 / 非 acrylic 回退档 | Win11 上全局归零，模糊只发生在 DWM 那一层 |

WebGL 不参与：`gl.readPixels` 只读自己的 framebuffer，拿不到窗口外像素。
也不需要内部极光 emissive mesh —— 那种发光体是离线 3D 光追的质感，
在文字密集的文件管理器里只会抢注意力。

### 10.4 动效与截图验收

- 200~300ms 淡入 + 上滑 8px；切分类 / 搜索结果逐项错开，上限 12 项；
- hover：`translateY(-2px)` + 阴影加深 + 一层极淡 cursor glow
  （`rgba(255,255,255,.32)`），不缩放；
- 三种显示模式（window / sidebar / dock）平滑切换，dock 反而更透；
- 文档截图统一垫 `src/main/backdrop.html` 的中性灰蓝合成桌面，
  由 `scripts/reshoot.py` 走系统全屏截图批量生成。早先蓝天草地那版本身太艳，
  会透过亚克力把整张图染成彩色，深色模式更是灰蓝一团看不出来。

## 十一、3.3：材质六步、自适应明暗与模式切换动效

3.2 解决了"玻璃能不能透出桌面"，3.3 解决"透出来之后像不像一块有厚度的玻璃"。
材质被拆成六步，顺序就是光走过来的顺序，全部落在 `src/renderer/styles/material.css`。

### 11.1 六步与实参

| 步骤 | 做什么 | 浅色玻璃 | 深色玻璃 |
|---|---|---|---|
| 1 投影 | 卡片先"落"在桌面上 | 接触影 1px + 中景 14px + 远景 38px，三层叠加 | 同样三层，全部压成黑色 |
| 2 模糊提亮 | 把背后的东西糊开再提亮 | `blur(2px) saturate(180%) brightness(1.06)` | `blur(2px) saturate(160%) brightness(0.8)` |
| 3 边缘折射 | 越靠边，背景越向内偏 | 边宽 44px，位移 1.1×边宽折算，色散 ±15% | 同左 |
| 4 着色 | 一层半透明色 | `rgba(255,255,255, 6%~22%)` | `rgb(20,20,24) 16%~38%` |
| 5 边缘光 | 左上、右下各一道，再向内收一道 | 顶 62% 白 / 底 10% 冷灰 | 顶 42% 白 / 底 28% 黑 |
| 6 文字着色 | 让字"长"在玻璃上 | 正片叠底 `multiply` | 叠加提亮 `screen` |

六步里最容易被忽略的是第 1 步。玻璃的通透感有一半来自**影子**：
影子越干净、层次越清楚，玻璃越像浮着；影子一糊，整块面板就退化成半透明贴纸。

### 11.2 折射：两条路，别混着走

Chromium 的 `backdrop-filter` 只能采样**页面自己画的东西**。窗口外的桌面由 DWM 绘制，
CSS 拿不到那些像素 —— 这是进程边界，不是写法问题。所以折射分两条实现：

- **solid 档（Win10 / 非 Windows）**：玻璃后面是我们自己画的 `.app-bg`，有起伏可折。
  边缘透镜用「外扩 9px 采样 + 44px 边缘蒙版 + clip-path 收回」做真位移：
  采样窗口比面板大一圈，画回原位时，边缘的内容就等于被拉向了中心。
- **acrylic 档（Win11）**：桌面在 DWM 那一侧，折不弯。改用**光学近似**：
  44px 边宽的弧形辉光 + 红蓝错位发丝线（红光偏折少落在外侧、蓝光偏折多缩在内侧）。
  眼睛读到的是同一件事 —— 这块玻璃有厚度、边缘在弯光 —— 但 GPU 代价是 0。

两种路径共用同一组令牌（`--lens-edge` / `--lens-shift` / `--disp`），
换档时只切实现，不切手感。

### 11.3 自适应：明暗看主题，厚度看背景

原先的规则是"采样背景亮度，低于 0.5 就把材质和文字一起翻深色"。这条规则有三个问题，
线上被一张绿色壁纸打穿：

1. 采样时窗口已经盖住了大半屏幕，兜底逻辑把**我们自己的窗口**算进了平均值，
   判断直接反过来 → 浅色玻璃配浅色字；
2. 就算判断对了，用户选了浅色模式却得到深色玻璃，预期落空；
3. 全局平均值对"上半亮下半暗"的壁纸毫无意义。

现在的模型把一件事拆成两件：

- **明暗 = 主题。** 浅色模式永远是浅色玻璃 + 深色字，深色模式永远反过来。可预期。
- **厚度 = 背景亮度。** 开窗**之前**用 `desktopCapturer` 采一张 64×36 的桌面亮度表
  （此刻窗口还不存在，采到的是干净壁纸），之后按每个面板的屏幕矩形查表，
  算出需要多少白色填料才能把表面亮度推到 0.72（深色模式 0.22）：

  ```
  alpha = (target - L) / (tintLum - L)   // 背景已达标时只铺 5%
  ```

  背景本来就亮 → 5%，薄如蝉翼；背景偏暗 → 填料加到 60%~70%，
  宁可厚一点，也不让 11.5px 的说明文字糊在背景里。

代价是诚实的：**深色壁纸 + 浅色模式**这一组不可能同时又透又清楚，
系统只能选清楚。想要通透就把主题切到深色——深色玻璃在深色背景上只铺 5%。
`--mist` 滑块仍然保留，用来按回桌面的色温，不再承担可读性。

### 11.4 模式切换动效

出处是那篇《12 项动效原则》。12 条里能落到"窗口换形态"这个场景的有五条，
其余（挤压拉伸、弧线之外的时间控制）用不上，就不硬套：

| 原则 | 落地方式 |
|---|---|
| 预备动作 Anticipation | 切换前 90ms 先缩到 0.988、透明度 0.92 |
| 缓入缓出 Ease in/out | 420ms `cubic-bezier(0.16,1,0.3,1)`，落定不弹 |
| 弧线 Arcs | 位移走带中点的关键帧，不是直线平移 |
| 跟随与重叠 Follow through | 标题栏 / 工具栏 / 轮盘 / 列表 / 状态栏按 0/40/60/80/120ms 依次落位 |
| 次级动作 Secondary action | 一道 460ms 的高光扫过，把"窗口尺寸跳变"这一下盖住 |

窗口尺寸本身是瞬间改的（`setBounds` 逐帧补间在 Windows 上会掉帧，还会让亚克力闪），
所以动画只做内容层：先缩 → 换尺寸 → 从锚点方向展开。锚点跟着模式走 ——
悬浮挂件长在右下，侧栏长在屏幕左/右，窗口模式从中心散开。

### 11.5 这版修掉的两个真 bug

1. **切到侧栏 / 悬浮模式后回不来**：设置按钮原本只在侧栏底部，而紧凑模式第一条规则就是
   `.sidebar { display: none }`。同一个 `@media (max-width: 720px)` 还把设置弹窗里的
   「显示模式」分段控件一起收掉了。现在标题栏常驻一组紧凑控件（设置 + 回到窗口模式），
   设置弹窗在窄窗口里改成竖向排布并铺满可用区域。
2. **折叠详情栏时卡片被切**：折叠用的是 `width:0 + margin-right:-318px`，
   负外边距让弹性容器把多出来的 318px 分给了 `.main`，而详情栏在 `.main` 之后，
   于是 `.main` 反而变宽、把最后一列卡片顶出窗口。折叠改成 `display:none`，
   不参与弹性布局，也就没有可分配的空间。

## 十二、3.5：把苹果那七层落到 CSS 里

四篇拆解读下来，苹果 Liquid Glass 的模型是**七层**，不是"加个模糊"：

| # | 层 | 苹果怎么算 | 我们在 CSS 里怎么近似 |
|---|---|---|---|
| 1 | 背景 | 环境内容被模糊与色彩影响 | `backdrop-filter: blur(20px) saturate(180%)` |
| 2 | 形状 | SDF 定义边界，圆角/宽度可实时改 | `border-radius` + 单层径向蒙版（不用 mask-composite） |
| 3 | 染色 | 半透明色彩填充 | **3%~4%**，只让玻璃"存在"，不遮背景 |
| 4 | 折射 | 按法线偏移背景采样坐标，边缘弯、中心平 | 边缘 1px 色散线 + 内收壁厚线（桌面在 DWM 那侧，CSS 折不弯） |
| 5 | 高光 | 光源 + 法线实时算，形状变高光跟着变 | 左上亮边 + 一道 14s 绕边的流动高光 |
| 6 | 色散 | RGB 三通道用略微不同的坐标采样 | 暖色在外、冷色在内各一道 1px 发丝线 |
| 7 | 阴影 | 柔和接触阴影 | 三层投影（接触 / 中景 / 远景） |

### 12.1 为什么把底色降到 4%

3.3/3.4 为了让字清楚，把白色填料加到 6%~22%，还按面板背后的亮度分别算 ——
结果同一个窗口里三块玻璃厚薄不一，用户看到的是"一个模块浅、另一个模块深"。
这一版反过来：**底色只负责"这是一块玻璃"，可读性交给文字本身**（深色字 + 一道极轻投影），
厚度做成一个 0~30 的滑块（默认 0 = 全通透），背后太花时由用户自己加。

### 12.2 液态流动怎么做的

`@property --flow-angle` 注册成 `<angle>`，让 conic-gradient 的起始角可以被动画插值；
伪元素上用一层沿边缘可见的锥形高光，14 秒转一圈。蒙版只用**单层径向渐变**，
因为四层线性 + `mask-composite` 在部分 Chromium 上会退化成整块全遮 ——
那等于给整个面板盖了层高光，表现就是"字发糊"（3.4 踩过这个坑）。

### 12.3 这一版修掉的三个真 bug

1. **字一直发灰**：`glass.css` 在 `tokens.css` 之后加载，里面又把 `--ink-3/--ink-4`
   写死成 `#5f6675/#7e8593`。于是 3.4/3.5 在 tokens 里怎么调深都没用。
   现在颜色只在 tokens 一处定义。
2. **模块明暗不统一**：`glass.css` 给 `.sidebar/.main/.details` 各自写死了 5%/8%/12% 的白，
   还分浅色/深色/dock 三套。加上新的 `.glass` 材质后，两套规则打架，谁加载后谁赢。
   现在底色只由 `.glass` 决定。
3. **切到侧边栏/悬浮就只剩 C 盘**：`lastFolder` 只读不写，任何一次重启都会退回主目录。
   现在每次导航防抖 800ms 写回。

### 12.4 性能

搜索从"整棵树 stat 一遍再过滤"改成"先按文件名筛、只 stat 命中的"：
3000 个文件的目录，一次搜索从"要等"变成 98ms（含 200 条命中与相似推荐）。
